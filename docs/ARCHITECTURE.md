# AnchorShell Architecture

## 1. Architecture rule

**GUI intent is not tied to one protocol.**

The frontend requests operations. The Rust backend plans and executes them using the best supported backend.

```text
React / TypeScript UI
        |
        v
Tauri command boundary
        |
        v
Operation Planner
        |
        +--> SSH
        +--> SFTP
        +--> remote native command
        +--> tar-over-SSH
        +--> rsync
        +--> local Windows filesystem
        |
        v
Progress / cancellation / audit events
```

## 2. Technology baseline

### Frontend

- React
- TypeScript
- Tailwind CSS
- xterm.js

### Native/backend

- Rust
- Tauri 2
- Tokio async runtime
- SQLite
- SSH/SFTP library selected during G1 with explicit compatibility tests

### Windows automation

- PowerShell 7 is the preferred automation surface
- Windows PowerShell 5.1 may be supported for compatibility
- PowerShell is not the core execution engine

## 3. Core modules

Target Rust module boundaries:

```text
src-tauri/src/
├─ app/
├─ connection/
├─ ssh/
├─ sftp/
├─ transfer/
├─ fileops/
│  ├─ planner/
│  ├─ sftp_backend/
│  ├─ native_backend/
│  ├─ tar_backend/
│  └─ rsync_backend/
├─ tunnel/
├─ terminal/
├─ ops/
├─ automation/
├─ vault/
├─ persistence/
├─ safety/
└─ windows/
   ├─ powershell/
   ├─ filesystem/
   ├─ shell/
   ├─ credentials/
   ├─ explorer/
   └─ wsl/
```

Do not create these modules until code requires them. This is a boundary map, not a requirement to create empty directories.

## 4. Operation model

Every substantial operation has:

- operation ID
- host/session ID
- intent
- selected backend
- state
- progress
- cancellation token
- human-readable execution plan
- result
- audit summary

Suggested states:

```text
planned
queued
running
cancelling
completed
failed
cancelled
```

## 5. Connection model

One logical host may have multiple channels but should reuse a connection where safe.

```text
Host Session
├─ terminal channels
├─ SFTP channel
├─ exec channels
└─ tunnel channels
```

Connection ownership, reconnect policy, and concurrency limits belong to Rust.

## 6. PowerShell boundary

PowerShell calls the same application operation API as the GUI.

Do not build a second implementation.

```text
GUI ---------------------+
                         |
PowerShell module -------+--> AnchorShell command/API boundary
                              |
                              v
                         Operation Planner
```

## 7. Security rules

- secrets are never logged
- shell commands generated by the planner must use rigorous argument quoting
- destructive operations must pass canonical-path safety checks
- private keys remain local unless the user explicitly exports them
- host-key verification is mandatory
- release artifacts are produced in GitHub Actions
- signing is added before stable release

## 8. Performance principles

- avoid per-file network round trips when a remote-native operation can do the work locally
- stream large transfers
- bounded concurrency
- backpressure on UI event streams
- avoid loading whole files into memory
- keep idle timers dormant where possible
- measure before adding complexity
